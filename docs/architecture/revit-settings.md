# Per-user Revit settings

Issue #60 moves editable SolidGround preferences to `%LocalAppData%\SolidGround\Revit\settings.json`. The older `%ProgramData%\SolidGround\Revit\settings.json` remains a read-only legacy-import source. A missing per-user file is normal first use: the property workflow receives valid guided-fetch defaults and does not create a placeholder raster configuration before opening its modal UI.

`UiSettingsDocument` begins at `schemaVersion: 1`. It is strict: unknown or missing fields, unsupported versions, invalid tokens, invalid request values, and non-finite or out-of-range extension/distance values are named as repairable settings errors. It persists a canonical `terrainExtensionMeters` double without display rounding, and a separate `distanceDisplayFormat` token. It does not serialize credentials or the shared-coordinate write option.

The store captures the SHA-256 digest of the exact bytes (or an explicit `missing` sentinel) with an immutable draft. Save serializes and validates the already-selected draft, takes a named mutex, compares the target digest before staging and immediately before publishing, then atomically replaces the target. A conflict preserves the file and draft and asks the operator to reload or reapply; it never decodes and overwrites a competing writer's bytes.

An invalid, malformed, duplicated-member, or future-version per-user document is never replaced by opening Settings or by ordinary Save. The editor displays its field-specific repair error, preserves the exact bytes, and blocks Save until the operator explicitly chooses **Start new settings** and then chooses Save. Cancel leaves the invalid document unchanged. Declining a valid legacy import cancels the command rather than silently creating a default draft.

Legacy migration must preserve legacy bytes. When only the legacy file exists, the operator visibly chooses Review and import, Start new settings, or Cancel; no old configuration is silently activated. Every relative parcel, raster, PRJ, and source-sidecar path is resolved from the directory of the settings document that supplied it, through `SettingsPathResolver`, never from Revit's working directory. An imported legacy parcel buffer becomes the canonical terrain-only extension and the preserved legal parcel buffer is reset to zero. The shared-coordinate opt-in is cleared, and an explicit Save is required to publish a per-user snapshot.

The Settings ribbon command uses only WPF and settings services. It has no active-document dependency and opens no Revit transaction. Revit 2027 API verification for the command interface, transaction/regeneration attributes, `UIControlledApplication.CreateRibbonPanel`, `RibbonPanel.AddItem`, and `PushButtonData` is retained in `docs/architecture/revit-2027-verification-and-host-design.md`; this issue adds no new Revit API call.

Session credential overrides are held only in private process-memory references. An entered key has precedence over that provider's environment key, remains available while Revit runs, and is cleared on explicit Clear or `IExternalApplication.OnShutdown`. Settings JSON, logs, diagnostics, exports, provenance, and clipboard flows never receive the value.

County registrations are still machine-local and ship with no real service. The Settings dialog can create one without hand-edited JSON: the operator enters the county source identity and five-digit GEOID, supplies a query-free HTTPS ArcGIS service URL, fetches its advertised layers and fields, selects parcel-ID/situs-address/optional legal-description mappings, supplies the county's attribution and verbatim license/disclaimer, and explicitly acknowledges authorized use. It then validates the selected layer and fields against the retrieved metadata and writes the local registry atomically through `CountyParcelRegistry.Write`; Settings Save persists the resulting registry path. Metadata discovery does not itself authorize a provider. Local GeoJSON and WKT parcel files remain an alternative source path.
